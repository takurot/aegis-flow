# CorridorPricing の区間積分（Issue #28）

SPEC §11.4 の純粋な料金演算を `contracts/src/CorridorPricing.sol` に実装する。内部ライブラリの `quote(capacity, recovery, work, q, base, surge, threshold)` は、指定された1レーンの回復後使用量と要求に対する USD8 料金を返す。レーン選択・回復時刻の更新・料金徴収・token 換算・管理権限・市場への有効化は含まない。テスト用 `PricingHarness` は実 EVM で演算を照合するための入口。

## 入力契約

すべて `uint256` で受け取り、無検証の narrow cast は使わない。

| 入力 | 単位・範囲 |
| --- | --- |
| capacity=L | USD8 整数、`1 <= L <= 10^18`（最大100億 USD） |
| recovery=T | 秒、`1 <= T <= 2^32-1`。上限は演算の対応範囲であり推奨設定ではない |
| work=w | 回復適用後の USD8×秒、`0 <= w <= L*T`。使用量 `w/T` の端数を保持する |
| q | 正の依存増分の USD8 整数、`0 <= q <= L`、`w+q*T <= L*T` |
| base=b / surge=p | bps 整数、それぞれ0〜10000、かつ `b+p <= 10000` |
| threshold=t | bps 整数、`0 <= t < 10000` |

設定不正は `InvalidParameters`、work と要求の容量超過は `CapacityExceeded` を返す。大きな q/work/rate も乗算前に拒否する。q=0 の料金は0。EXEMPT 相当の b=p=0 でも容量条件は検証し、無料を無制限枠と混同しない。上限を広げるには以下の演算証明と differential test を更新する。

## 厳密な整数演算

回復後の `w0=w`、消費後の `w1=w+q*T`、`d=10000-t` とする。SPEC の分数使用率を整数式へ代数変形する。

```text
z_i = max(0, 10000*w_i - t*L*T)
D   = 400000000 * L^3 * T^4 * d^3
N   = q*b*D + 10000*p*(z_1^4 - z_0^4)
fee = ceil(N / (10000*D))
```

これは `q*b/10000 + L*(1-t/10000)*p/10000*(x1^4-x0^4)/4` と同じ有理数である。閾値・使用率を WAD 等に丸めない。2つの256-bit limb で積・差・和を正確に保持する。最後は `N <= 10000*D*fee` を満たす最小の整数を `[0,q]` 内の二分探索で求める。限界料率は `(b+p*x^3)/10000 <= 1` なので、この上限で厳密な ceil を表現できる。

対応範囲では `L<2^60`、`T<2^32`、`d,b,p<2^14`。以下は厳密な上界であり、測定結果の推定ではない。

| 中間値 | 上界 |
| --- | --- |
| z | `<2^106` |
| z の二乗 / 四乗 | `<2^212` / `<2^424` |
| D | `<2^379` |
| q*b*D | `<2^453` |
| 10000*p*四乗差 | `<2^452` |
| N | `<2^454` |
| 10000*D | `<2^393` |
| 比較用の 10000*D*fee | `<2^453` |

z の二乗までは uint256 内、それ以後は512 bits 内に収まる。full multiplication は high/low の両方を取得し、上位 limb の積・carry は checked arithmetic を使う。下位 limb の wrap は carry/borrow と合わせて処理する。四乗差は w1>=w0 により非負。二分探索は最大60回程度で終わる。

## 検証した結果と保証範囲

- L=$2M、t=6000、b=5、p=1500: 60→100% の $800k は **$30,400**、0→100% は **$31,000**。
- 同じ全量区間で p=4000 は **$81,000（4.05%）**。攻撃利益・資金拘束・gas を含む不採算の証明ではない。
- 同一レーン・同一設定・回復なしの N 分割では積分が加法的で、`0 <= split-single <= N-1` USD8 最小単位。100分割とファズで確認する。別レーン、途中の回復、第三者取引、設定変更では同じ積分区間にならず、この差分上限を流用しない。
- Python `Fraction` の参照式は Solidity の整数変形式とは別に SPEC の使用率式から計算する。実 Anvil に配置した harness を、最大値・閾値0/9999・分数 work・q=0・EXEMPT と固定 seed=28 の256生成例、計263ケースで照合し、すべて一致した。
- ライブラリは純粋演算で状態を変更しない。失敗時の残量・ポジション・徴収の原子性は #30、回復と設定変更は #27/#33 の後続責務。借入資産への換算丸め・slippage は本ライブラリの出力と別に検証する。

正確さを優先する現実装の料金演算には複数回の512-bit 比較が必要。実市場の通常借入に対する追加 gas 8,500 以下を達成したとは扱わず、#22 の計測・統合ゲートを維持する。独立監査と対象市場実証前に本番有効化しない。
