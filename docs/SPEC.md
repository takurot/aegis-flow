# aegis-flow 機能仕様書

- 版: 0.1（設計案）
- 基準資料: [IDEA.md](IDEA.md)
- 状態: 実装前。数値は評価用の初期値であり、本番保証や採用済み設定ではない。

## 1. 目的と対象範囲

担保を多数のアドレスに分散して短時間に借り入れる行為に対し、保護対象のレンディング市場で、未熟成担保に依存する新規借入の流量を制限する。汚染情報による追加制限、隔離保管、証明による例外、および再現可能なバックテストを提供する。利用者は通常の供給、返済、引き出し、清算も利用できる必要がある。

**保護境界**は、すべての担保変更・借入・負債移転を Aegis の状態機械が検証し、迂回不能であることを統合先が保証した、単一チェーン上の単一市場とする。直接 Pool を呼べる市場に単なる任意利用のラッパーを追加しても市場全体は守れない。Aave V3 は Pool 自体が利用者向け操作を公開し、V4 は Hub と市場ごとの Spoke で構成される（[V3 Pool](https://aave.com/docs/aave-v3/smart-contracts/pool)、[V4 概要](https://aave.com/docs/aave-v4)）。V3 の強制統合方法、V4 の対象 Spoke と拡張点は未確定であり、適合性確認まで既存市場の保護を主張しない。

対象候補は Ethereum、Arbitrum、Base、Optimism。チェーンごとに実際の統合先、オラクル、最終性、データ取得、EIP-1153 対応を検証して有効化する。チェーン間に共有バケットはない。対象外は盗難資金の完全な識別、検閲回避、全 DeFi 市場の保護、および損失ゼロの保証。

### 成功条件

1. 有効な価格と統合境界の下、証明例外を除く未熟成依存の借入増加額は、その市場の各エポック容量以下である。
2. 汚染の通知は対象の資産・担保量に限定し、無関係な担保やアドレス全体を一律凍結しない。
3. Sentinel 停止時もオンチェーンの借入制限が成立し、返済と清算を妨げない。
4. 実事件の評価は入力、ラベル、前提、カバレッジを添えて再現可能にする。目標値は測定結果とは区別する。

## 2. 役割と信頼境界

| 役割 | 操作・権限 | 信頼上の注意 |
| --- | --- | --- |
| 利用者／借り手 | 供給、借入、返済、引き出し、状態照会、必要なら証明提出 | コントラクト・第三者代行を含む。借入の債務者と受取人を区別 |
| 清算人 | 統合先の清算操作 | Sentinel、バケット、証明から独立。統合先の清算条件は引き続き適用 |
| Sentinel 運用者 | 検知・根拠保存・汚染通知の提案／送信 | 誤検知・鍵侵害があり得る。通知は資産量と権限で制限 |
| リスク管理者 | パラメータ、資産、オラクル、検知シードの変更提案 | マルチシグとタイムロックを原則とし、変更を監査可能にする |
| 緊急管理者 | 新規借入の一時停止、通知者の権限停止 | 単独で利用者資産を移動できない。返済・清算は停止しない |
| 証明・ルート発行者 | 将来の例外証明用の集合とルートの管理 | 例外経路は定義と監査が完了するまで無効 |

統合先、価格フィード、管理鍵、ブリッジやデータソースは信頼依存先である。複数管理者の閾値、タイムロック時間、緊急権限と失効手順はデプロイ前に確定する。

## 3. 基本パラメータと単位

| 項目 | 評価用初期値 | 意味 |
| --- | --- | --- |
| 熟成期間 `T` | 2 時間 | 各担保ロットの供給時刻からの経過時間。境界は `now >= suppliedAt + T` |
| エポック長 `E` | 600 秒 | Unix 時刻を基準とする固定窓。`epoch = floor(timestamp / E)` |
| 容量 `K` | 2,000,000 USD | 市場全体の窓あたりの未熟成依存の新規借入上限 |
| 追跡ホップ上限 | 15 | Sentinel の暫定解析範囲。未追跡を無汚染とみなさない |
| 価格単位 | USD、内部精度と上限は実装時確定 | 資産ごとの decimals、価格精度、丸めを明示 |

すべての担保を金額の大小にかかわらず熟成対象とする。IDEA の大口閾値のみを対象にすると少額分割で迂回できる。上記数値はガバナンス決定前の実験値である。エポック長・容量の変更は旧窓終了時に適用し、その時点を新窓の起点とする。旧窓中の残量は復元せず、新窓は新容量で開始し、以後は新起点から新しい長さの窓を数える。設定版を窓 ID に含め二重初期化を防ぐ。熟成期間変更は変更前ロットの満期を短縮しない。価格変動と利息による再評価は発生するが、過去窓の消費を遡及修正しない。

## 4. オンチェーン機能要件

### 4.1 状態と会計

各担保ロットに市場、債務者、資産、実受領数量、供給時刻、満期、隔離状態、汚染数量を記録する。複数回供給しても古いロットの満期をリセットしない。ロット分割・部分引き出しは数量と汚染数量を保存し、引き出し対象は最も新しいロットからとする。移転可能な担保証票、担保の第三者への移転、債務委任、eMode 等の経路は、統合先で正しく追跡・検証できなければ無効化するか、その市場を保護対象外とする。利息・リベース・手数料徴収型トークンの数量対応は統合実装で実証するまで非対応とする。

汚染量は `0 <= tainted <= 保護対象ロットの実数量`。同じ証拠の再送は加算しない。資産・ロットごとに指定し、対象に実在しない残高や未関連資産に適用しない。汚染を他ロットに移して健全な担保を制限してはならない。外部ウォレットへの着金だけでは担保ロットは作らずロックもしない。汚染指定が遅延した場合は、その時点の紐付け可能な対象担保に限る。事後通知による既存債務の強制清算は行わない。

引き出し・清算では対象資産について供給順の逆順（同時刻はロット ID の降順）にロットを消費し、各ロットの部分消費では汚染数量を消費数量の比率で按分する。端数は汚染を過小評価しない向きに丸め、消費部分と残存部分の合計を元の汚染数量と一致させる。移転を許可する統合ではこの属性を移転先に保存し、保存できなければ移転を拒否する。適用可能な清算処理はこの拒否によって阻害しない設計を統合ゲートとする。

価格を用いて、汚染控除後の各ロットの借入可能価値を `数量 × USD価格 × 統合先の適用LTV` で求める。合計を熟成済み `S`、未熟成 `U` とする。複数資産、担保設定、LTV、既存負債と利息は統合先の実状態に一致させ、追加の制限を加える前に統合先の健全性条件も必ず満たす。汚染控除は担保数量ベースで行い、0.01 USD 相当の汚染が正常担保全体のロックにつながらないようにする。ただし既存債務により新規借入余力の減少幅は変動する。

### 4.2 供給・借入・返済

1. **供給**: 実受領量を確定しロットを作成。未熟成の開始時点はオンチェーンのブロック時刻。供給だけでバケットは消費しない。ゼロ量、未対応資産、受領量不整合は拒否する。
2. **借入**: 債務者の価格換算後の全既存債務を `D`、今回の借入額を `x` とする。借入前後で同一の価格・担保状態を使用し、未熟成依存の増分を `q = max(0, D + x - S) - max(0, D - S)` とする。`D + x <= S + U` と統合先の借入条件を満たし、かつ `q <= 窓の残量` の場合のみ許可し、原子的に `q` を消費する。失敗時は状態をすべて戻す。`q = 0` の借入はバケットを消費しない。価格換算は担保価値を切り下げ、債務・消費額を切り上げる。
3. **返済**: 統合先の返済を許可し、同一窓でも消費済みバケットは戻さない。借入・返済の繰り返しによる再利用を防ぐ。
4. **引き出し・担保無効化・利用者による担保移転**: 統合先の健全性に加え、変更後の `D <= S + U` を満たす場合に許可する。ただし事後汚染等で既に不等式を満たさない場合、担保不足を悪化させない操作のみ許可する。さらに、変更前後で同じ価格・負債を用い、`q_change = max(0, D - S_after) - max(0, D - S_before)` の正の部分をバケットから原子的に消費する。残量不足なら拒否する。これにより熟成担保を引き出して既存債務の裏付けを未熟成担保へ移す迂回を防ぐ。利用者起因のその他の担保構成変更・債務移転も同じ増分会計を適用する。価格変動、利息、管理操作や清算による変化を遡及課金しないが、これらの後に利用者が行う操作には再評価後の状態を用いる。返済と清算はバケット不足を理由に拒否しない。
5. **清算**: 統合先の規則に従い実行し、対象ロットと債務を原子的に更新。バケット不足、Sentinel 停止、汚染指定、証明の有無を清算の拒否理由にしない。

固定窓は窓境界の直前・直後にそれぞれ `K` を許容するため、任意の 10 分間での流出を `K` 以下に抑えるものではない。金額は借入実行時点の評価額であり、後の価格変動、既存の成熟担保や借入、別市場・別チェーン、未保護経路を含む損失の上限ではない。熟成により汚染が自動解除されることはない。

同一トランザクションや同一ブロックの取引も上記の永続会計を適用する。暫定仕様では追加の同一ブロック一律拒否や時間比例の線形解放は採用しない。IDEA の式は供給直後に即時枠がゼロになる一方、即時共有枠を許す記述と矛盾するためである。EIP-1153 はトランザクション終了時に破棄されるため、同一ブロック内の別トランザクションを識別する代替にはできない（[EIP-1153](https://eips.ethereum.org/EIPS/eip-1153)）。

### 4.3 価格・失敗時の扱い

統合先が認めた資産ごとに価格ソース、最大経過時間、価格の単位、妥当な値域、L2 シーケンサー停止時の扱いを設定する。価格がゼロ、期限切れ、取得不能、範囲外、または演算オーバーフローの場合、影響する新規借入と担保削減は拒否する。返済と、統合先の安全な規則で実行できる清算は妨げない。価格障害中に安全に清算できるかは統合先に依存し、無条件の実行成功を保証しない。エラーは機械可読コードと市場・資産を返す。

### 4.4 汚染通知と解除

`flagTaint(evidenceId, user, asset, lotIds, quantities, expiresAt)` 相当の操作を認可済み Sentinel のみが呼ぶ。配列長、上限、重複、各数量、期限を検証し、証拠 ID 単位で冪等に適用する。根拠とロットの関連性はオンチェーンで自動保証できず、認可主体の判断に依存する。権限侵害による誤指定への対応として、権限停止、異議申立て、訂正、操作上限と監査が必要である。イベントに通知 ID、対象、数量、根拠への参照、送信者を残す。根拠そのものの秘密情報は公開しない。承認済みの解除権限は理由・証拠 ID を付して指定分を解除でき、履歴を残す。期限到来時の自動解除や通知の最大期間は未決定であり、決まるまでは期限切れ通知を新規に受け付けず、既存ロックの解除は明示操作とする。誤検知訂正と鍵漏えい時の停止・再登録の手順を運用要件とする。

### 4.5 隔離保管

隔離エスクローは市場本体と資産・利用者ごとに残高を分離し、未熟成の対象資産を保持する。原則として受領、成熟後の統合先供給、利用者への返還を公開イベント付きで行う。凍結・返還失敗は当該エスクローの失敗として記録し、他の預入者の処理を巻き戻さない。管理者による任意の資産引き出しは不可。

**実装上の前提**: エスクロー内資産は、統合先が検証可能な担保として認識し、清算・差押えが原子的に実行できる場合のみ借入を裏付けられる。そうでなければエスクロー残高の借入可能価値はゼロとする。借入後の発行者凍結は清算不能や損失を生じ得るため、隔離だけで市場の無傷を保証しない。隔離対象の判定、資産別凍結単位、清算設計と可用性を実証するまで本機能は無効。

### 4.6 証明による例外

初期仕様では ZK バイパスを**無効**とする。ブラックリストに単一アドレスが含まれないことは資金経路全体の潔白を証明せず、空・古いリスト、途中送金、DEX、ブリッジを通した資金や証明の使い回しを防げない。実装候補は限定された集合への所属等、証明できる命題として別途定義する。証明が保証する範囲を利用者に明示し、「無実」の保証と呼ばない。

有効化には少なくとも、対象となる資金と金額のコミットメント、出所と残高の検証可能な関係、資金混合の扱い、受益者・市場・チェーン・資産・上限・有効期限・操作への拘束、ルートの真正性と鮮度、失効、nullifier の原子消費、リプレイ防止、回路と検証鍵のバージョン管理、独立監査を仕様化し実証すること。無効・期限切れ・ルート不一致・既使用証明は拒否する。例外による借入は §1 のバケット保証には含まれない。

## 5. Sentinel 機能要件

### 5.1 取り込み・追跡

確定済み／未確定を区別したブロック、トランザクション、receipt、対応 ERC-20 Transfer を取り込む。イベント ID は chain ID・block hash・transaction hash・log index とする。順序、再送、欠落を検出し、永続チェックポイントから再開できる。Pending 情報は観測可能な範囲の予測であり、確定イベントと区別する。プライベート取引、L2 sequencer、ノード差により観測や先回りを保証しない。

シードは出典、資産、数量、対象期間、登録者を持つ。ノードは時刻・トランザクション順序を含むイベント単位とし、同じアドレス間の往復も DAG として表現する。資金の混合時は資産ごとに数量と汚染割合を持つ比例配分（haircut）を用い、送付数量の `汚染残高 / 総残高` 相当を伝播する。小数・丸め・過去残高の基点を記録し、残高不明や履歴欠落は unknown とする。FIFO と比例配分は異なるため混用しない。複数シードの重複や自己送金による二重計上を防ぐ。実行可能な DEX・ブリッジの解釈器を個別登録し、未対応経路では推測で無汚染としない。上限ホップ、欠落、計算量制限到達は coverage に記録する。

### 5.2 再編成と通知

ブロック親ハッシュを検証し、reorg 発生時は共通祖先までロールバックし正規チェーンを再実行する。通知候補には根拠ブロックと最終性を含める。確定前通知の許容条件と補償手順を設定し、取り消された根拠に基づくロックは明示解除を提案・実施する。オンチェーン操作自体が reorg された場合は receipt と状態を照合して再送する。

通知のライフサイクルは `candidate → submitted → included → finalized`、失敗時は `failed/retry`、根拠喪失時は `retracted` とする。高優先手数料やバンドルを使っても相手より先に確定する保証はない。nonce、手数料上限、再送、冪等性、重複インスタンスのリーダー選出と鍵保護を設け、送信成功を最終確定と扱わない。検知が間に合わない場合も §4.2 の制限が独立して働く。

### 5.3 運用観測

取得遅延、最終処理ブロック、reorg、欠落、unknown 割合、候補・送信・確定・失敗数、オンチェーン残量、通知遅延と価格鮮度を記録し、閾値超過で通知する。鍵・秘密入力・個人情報はログに出力しない。ノード停止・再起動・障害からの復旧と照合手順を用意する。

## 6. シミュレータ

### 6.1 入力と実行

ブロック順の供給、借入、返済、引き出し、清算、移転、価格、対象市場設定と攻撃ラベルを読み込む。各データセットのチェーン、ブロック範囲、出典、取得時刻、ハッシュ、欠損、ラベル根拠を manifest に記録する。時刻や金額、重複・順序・スキーマを検証し、不足する価格やイベントは成功扱いせず、該当結果を `hold` または `failed` とする。Parquet は候補形式であり Rust/Polars の利用は実装上の選択肢。

実行はベースラインと同一入力・順序の対策ありシナリオを比較し、パラメータ、コード版、データ hash、乱数 seed、前提を保存する。拒否された取引後の行動は観測できないため、再試行・取引順序・価格への影響などの仮定を明示し、観測事実と反実仮想を分離する。再試行や経路変更をモデル化しない場合、その制約を出力する。

### 6.2 指標

| 指標 | 定義 | 評価目標 |
| --- | --- | --- |
| 被害阻止率 | `(ベースラインの攻撃者借入 USD - 対策後の攻撃者借入 USD) / ベースラインの攻撃者借入 USD` | 95% 以上を目標。分母ゼロは N/A |
| 正常ユーザー摩擦率 | 制限で拒否または延期された正常借入件数 / 評価可能な正常借入件数 | 0.05% 未満を目標。正常ラベル不明は分母から除き件数を別記 |
| 清算干渉率 | Aegis の追加制限で失敗・延期された評価可能な清算件数 / 評価可能な清算件数 | 0%。統合先固有の失敗は別集計 |
| カバレッジ | 評価可能な操作数 / 対象操作数 | 欠損理由と併記。閾値はデータ選定時に確定 |

件数・分母・未判定数・資産価格時点・期間・シナリオごとの値を出力し、未達や N/A を隠さない。IDEA にある事件名、具体的被害額や阻止額は検証前の例示であり、実績として扱わない。

## 7. 外部インターフェースと状態遷移

実装の ABI は統合設計の確定後に定義する。最低限の論理操作は `supply(user, asset, amount)`、`borrow(debtor, asset, amount, recipient)`、`repay`、`withdraw`、`liquidate`、`flagTaint`、`clearTaint`、`getBorrowStatus`、パラメータ変更と緊急停止である。呼び出し元、債務者、担保所有者、受取人の認可は統合先に整合させる。プレビューは価格・残量・ブロック時点を返し、次の取引成功を保証しない。

ロットの状態は `Unseasoned → Seasoned` を時刻条件で導出し、汚染は独立した数量属性、隔離は独立した保管属性とする。部分引き出し・清算で数量を減らし、残量ゼロなら終了。操作ごとに `SupplyRecorded`、`BorrowValidated`、`BucketConsumed`、`TaintFlagged/Cleared`、`Escrow*`、`ParameterScheduled/Activated`、`PauseChanged` を出力する。イベントに市場、対象、数量、単位、バージョンを含める。状態遷移とイベントは同一トランザクションで確定する。

## 8. 非機能要件と検証

性能は目標であり、ハードウェア、コンパイラ、ノード、データ規模、ウォームアップ、分位点、計測範囲を固定してから判定する。通常借入の追加ガス `8,500 以下`、Sentinel の 10,000 Transfer / block を 5 ms 以内、証明生成 1.5 秒以内・検証 220,000 gas 程度は IDEA 由来の**未検証目標**。ロット数や外部呼び出しによっては達成できず、保証ではない。10,000 件 / 5 ms と 1 件 / 50 μs は別の測定条件であり同一視しない。bounded な処理、超過時の拒否と監視を設計し、DoS を防ぐ。

ロット数の上限と到達時の供給拒否・統合規則を実装前に確定する。上限下での最悪ガスを測定し、ロット数の増加や上限到達を理由に返済・清算が実行不能にならないことを導入ゲートとする。

| 検証 | 受け入れ条件 |
| --- | --- |
| 単体・境界 | ロットごとの満期、価格小数・丸め、固定窓の境界、複数資産、返済後再借入、価格失効を検証 |
| 不変条件・ファズ | 同一窓内の非例外 `q` と正の `q_change` の消費合計が `K` 以下、残高と汚染量が保存され負にならない。120/1,000 分割、マルチコール、複数借入、順序変更を含む。熟成担保で借入後に熟成担保を引き出し、未熟成担保へ債務を付け替える操作は残量不足なら拒否する |
| Dust | 保護外への微小送金では担保がロックされず、保護対象への汚染は当該数量以下。重複通知と複数資産も検証 |
| 故障・運用 | Sentinel 停止、RPC 欠落、reorg、誤通知の解除、再送、鍵権限取り消し、価格停止を再現。取引 revert 時の残量復元、窓長・容量変更、境界直前直後と市場・チェーン間の独立性も検証。借入は規則通り拒否され、返済・安全な清算が可能 |
| 統合・E2E | 選定した実市場のフォーク上で全借入・債務移転・担保移転経路の迂回不能性、ロット会計、清算と隔離障害を検証。未実現なら市場保護は未達 |
| 証明 | 有効化前に別途、偽証・別市場／別チェーン再利用・古い根・金額変更・nullifier 競合を検証し、独立監査 |
| シミュレーション | manifest から同一結果を再現。欠損を hold とし、全 KPI の分母・範囲・ラベル根拠を検証 |

## 9. 導入順序と本番ゲート

1. **データとシミュレーション**: 対象市場と事件のデータ利用可否を確認し、入力検証・ベースライン・反実仮想を実装。計測不能な KPI は保留する。
2. **統合可能性の実証**: 対象市場の全操作経路と権限、担保・債務・清算の状態を列挙し、迂回不能な強制点をフォークで証明。成立しなければ当該市場への導入を停止。
3. **オンチェーン制御**: エポック、ロット、会計、価格障害、権限を実装し、不変条件と E2E を通す。ガス・ロット上限を測定。
4. **Sentinel と隔離**: 検知、reorg、再送、手動訂正を結合。隔離の担保認識と清算可能性は別ゲートで実証。
5. **証明例外**: 命題と信頼モデルを確定し、回路・統合・監査が完了した場合のみ有効化。

本番導入前に、対象チェーンと市場の特定、統合先承認、パラメータ・権限・オラクルの確定、脅威モデル、独立監査、障害訓練、ロールバック・移行計画、監視とオンコール、実データによる受け入れ結果を揃える。緊急停止時の既存ポジションの管理と復旧手順を検証する。

## 10. 未決事項

- V3／V4 の具体的統合先、強制ポイント、対象市場・資産、移行と既存ポジションの取り扱い。
- 供給ロットの最大数とガス上限、利息・担保証票移転・清算との完全な整合方法。
- 価格フィード・鮮度・L2 停止時の具体設定、ガバナンスの閾値と遅延。
- 汚染の証拠基準、混合・DEX・ブリッジの対応範囲、異議申立てと解除期限。
- 隔離の清算可能性と発行者凍結時の損失負担。
- ZK が証明する厳密な命題と信頼モデル。実証・監査前は無効。
- 実データの入手・ライセンス・ラベル精度と評価対象、KPI の必要カバレッジ。
