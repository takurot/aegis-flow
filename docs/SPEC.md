# aegis-flow 機能仕様書

- 版: 0.4（設計案、Rev.2 多観点レビュー反映）
- 基準資料: [IDEA.md](IDEA.md)
- 状態: 開発基盤と入力検証を開発中。貸借保護機能は未実装。数値は評価用の初期値であり、本番保証や採用済み設定ではない。

## 1. 目的と対象範囲

担保を多数のアドレスに分散して短時間に借り入れる行為に対し、保護対象のレンディング市場で、未熟成担保に依存する新規借入の流量を制限する。汚染情報による追加制限、隔離保管、証明による例外、および再現可能なバックテストを提供する。利用者は通常の供給、返済、引き出し、清算も利用できる必要がある。

**保護境界**は、すべての担保変更・借入・負債移転を Aegis の状態機械が検証し、迂回不能であることを統合先が保証した、単一チェーン上の単一市場とする。直接 Pool を呼べる市場に単なる任意利用のラッパーを追加しても市場全体は守れない。Aave V3 は Pool 自体が利用者向け操作を公開し、V4 は Hub と市場ごとの Spoke で構成される（[V3 Pool](https://aave.com/docs/aave-v3/smart-contracts/pool)、[V4 概要](https://aave.com/docs/aave-v4)）。V3 の強制統合方法、V4 の対象 Spoke と拡張点は未確定であり、適合性確認まで既存市場の保護を主張しない。

対象候補は Ethereum、Arbitrum、Base、Optimism。チェーンごとに実際の統合先、オラクル、最終性、データ取得、EIP-1153 対応を検証して有効化する。チェーン間に共有バケットはない。対象外は盗難資金の完全な識別、検閲回避、全 DeFi 市場の保護、および損失ゼロの保証。

### 成功条件

1. 有効な価格と統合境界の下、未熟成依存増分は基本モードでは各固定窓の容量以下、§11 の連続回復モードでは各レーンの流量包絡以下である。証明例外は別に扱う。
2. 汚染の通知は対象の資産・担保量に限定し、無関係な担保やアドレス全体を一律凍結しない。
3. Sentinel 停止時もオンチェーンの借入制限が成立し、返済と清算を妨げない。
4. 実事件の評価は入力、ラベル、前提、カバレッジを添えて再現可能にする。目標値は測定結果とは区別する。

## 2. 役割と信頼境界

| 役割 | 操作・権限 | 信頼上の注意 |
| --- | --- | --- |
| 利用者／借り手 | 供給、借入、返済、引き出し、状態照会、必要なら証明提出 | コントラクト・第三者代行を含む。借入の債務者と受取人を区別 |
| 清算人 | 統合先の清算操作 | Sentinel、バケット、証明から独立。統合先の清算条件は引き続き適用 |
| Sentinel 運用者 | 検知・根拠保存・汚染通知の提案／送信 | 誤検知・鍵侵害があり得る。通知は資産量と権限で制限 |
| リスク管理者 | パラメータ、資産、オラクル、検知シードの変更提案 | マルチシグとタイムロックを原則とし、変更を監査可能にする |
| 緊急管理者 | 新規借入の一時停止、通知者の権限停止 | 単独で利用者資産を移動できない。返済・清算は停止しない |
| 証明・ルート発行者 | 将来の例外証明用の集合とルートの管理 | 例外経路は定義と監査が完了するまで無効 |

統合先、価格フィード、管理鍵、ブリッジやデータソースは信頼依存先である。複数管理者の閾値、タイムロック時間、緊急権限と失効手順はデプロイ前に確定する。

## 3. 基本パラメータと単位

| 項目 | 評価用初期値 | 意味 |
| --- | --- | --- |
| 熟成期間 `T` | 2 時間 | 各担保ロットの供給時刻からの経過時間。境界は `now >= suppliedAt + T` |
| エポック長 `E` | 600 秒 | Unix 時刻を基準とする固定窓。`epoch = floor(timestamp / E)` |
| 容量 `K` | 2,000,000 USD | 市場全体の窓あたりの未熟成依存の新規借入上限 |
| 追跡ホップ上限 | 15 | Sentinel の暫定解析範囲。未追跡を無汚染とみなさない |
| 価格単位 | USD、内部精度と上限は実装時確定 | 資産ごとの decimals、価格精度、丸めを明示 |

すべての担保を金額の大小にかかわらず熟成対象とする。IDEA の大口閾値のみを対象にすると少額分割で迂回できる。上記数値はガバナンス決定前の実験値である。エポック長・容量の変更は旧窓終了時に適用し、その時点を新窓の起点とする。旧窓中の残量は復元せず、新窓は新容量で開始し、以後は新起点から新しい長さの窓を数える。設定版を窓 ID に含め二重初期化を防ぐ。熟成期間変更は変更前ロットの満期を短縮しない。価格変動と利息による再評価は発生するが、過去窓の消費を遡及修正しない。

## 4. オンチェーン機能要件

§3・§4.2 の固定窓は基本モードの仕様。§11 を有効化した市場では固定窓リセットを廃止し、容量・q/q_change 会計を維持した連続回復を使う。同一操作に両モードを重ねて課金しない。

### 4.1 状態と会計

各担保ロットに市場、債務者、資産、実受領数量、供給時刻、満期、隔離状態、汚染数量を記録する。複数回供給しても古いロットの満期をリセットしない。ロット分割・部分引き出しは数量と汚染数量を保存し、引き出し対象は最も新しいロットからとする。移転可能な担保証票、担保の第三者への移転、債務委任、eMode 等の経路は、統合先で正しく追跡・検証できなければ無効化するか、その市場を保護対象外とする。利息・リベース・手数料徴収型トークンの数量対応は統合実装で実証するまで非対応とする。

汚染量は `0 <= tainted <= 保護対象ロットの実数量`。同じ証拠の再送は加算しない。資産・ロットごとに指定し、対象に実在しない残高や未関連資産に適用しない。汚染を他ロットに移して健全な担保を制限してはならない。外部ウォレットへの着金だけでは担保ロットは作らずロックもしない。汚染指定が遅延した場合は、その時点の紐付け可能な対象担保に限る。事後通知による既存債務の強制清算は行わない。

引き出し・清算では対象資産について供給順の逆順（同時刻はロット ID の降順）にロットを消費し、各ロットの部分消費では汚染数量を消費数量の比率で按分する。残存側の汚染を過小評価しない向きに丸め、消費部分と残存部分の合計を元の汚染数量と一致させる。証拠別残量は後述の claim 会計で更新する。移転を許可する統合ではこの属性を移転先に保存し、保存できなければ移転を拒否する。適用可能な清算処理はこの拒否によって阻害しない設計を統合ゲートとする。

価格を用いて、汚染控除後の各ロットの借入可能価値を `数量 × USD価格 × 統合先の適用LTV` で求める。合計を熟成済み `S`、未熟成 `U` とする。複数資産、担保設定、LTV、既存負債と利息は統合先の実状態に一致させ、追加の制限を加える前に統合先の健全性条件も必ず満たす。汚染控除は担保数量ベースで行い、0.01 USD 相当の汚染が正常担保全体のロックにつながらないようにする。ただし既存債務により新規借入余力の減少幅は変動する。

汚染数量は canonical な claim ID とロットの組で残量を持ち、同じ汚染部分を指す複数 evidence は同じ claim の根拠として紐付け、数量を二重加算しない。異なる claim は非重複の数量として登録し、集約汚染量をその残量の和とする。重複の関連性を判断できない根拠は保留し、推測で独立加算しない。ロット残量 Q から w を引き出し・清算する際は、汚染の残存総量を `ceil(taint*(Q-w)/Q)`、消費総量をその差とする。各 claim の残存割当は比例配分の floor 後、残余の大きい順（同率は claim ID 順）に単位を加え、総量と一致させる。各 claim の新残量は旧残量を超えない。移転では割当と根拠を移転先に保持する。

解除は指定 claim の現在のロット別残量以下に限り、原通知量や他 claim の量を使わない。根拠を一つ取り消しても同じ claim の別の有効根拠がある場合は数量を解除しない。ロット100、A10+B10から10消費した場合、A9+B9を保持し、Aだけの全解除は9とする。claim数の上限と重複訂正の履歴を定め、解除・配賦の計算量で清算を塞がないことを統合ゲートとする。

### 4.2 供給・借入・返済

1. **供給**: 実受領量を確定しロットを作成。未熟成の開始時点はオンチェーンのブロック時刻。供給だけでバケットは消費しない。ゼロ量、未対応資産、受領量不整合は拒否する。
2. **借入**: 債務者の価格換算後の全既存債務を `D`、今回の借入額を `x` とする。借入前後で同一の価格・担保状態を使用し、未熟成依存の増分を `q = max(0, D + x - S) - max(0, D - S)` とする。`D + x <= S + U` と統合先の借入条件を満たし、かつ `q <= 窓の残量` の場合のみ許可し、原子的に `q` を消費する。失敗時は状態をすべて戻す。`q = 0` の借入はバケットを消費しない。価格換算は担保価値を切り下げ、債務・消費額を切り上げる。
3. **返済**: 統合先の返済を許可し、同一窓でも消費済みバケットは戻さない。借入・返済の繰り返しによる再利用を防ぐ。
4. **引き出し・担保無効化・利用者による担保移転**: 統合先の健全性に加え、変更後の `D <= S + U` を満たす場合に許可する。ただし事後汚染等で既に不等式を満たさない場合、担保不足を悪化させない操作のみ許可する。さらに、変更前後で同じ価格・負債を用い、`q_change = max(0, D - S_after) - max(0, D - S_before)` の正の部分をバケットから原子的に消費する。残量不足なら拒否する。これにより熟成担保を引き出して既存債務の裏付けを未熟成担保へ移す迂回を防ぐ。その他の利用者起因変更では、影響を受ける各債務者 i について `delta_i=max(0,D_after_i-S_after_i)-max(0,D_before_i-S_before_i)`、`charge_i=max(0,delta_i)` とする。前後は同じ価格を使い、移転元の負の変化と移転先の正の変化を相殺しない。負債移転には D 固定の q_change 式を流用せず、両口座の負債・担保・枠・料金を原子的に検証する。割当先コリドーとレーンは各 charge_i の債務者から導出する。正しく評価できない移転は拒否する。価格変動、利息、管理操作や清算による変化を遡及課金しないが、これらの後に利用者が行う操作には再評価後の状態を用いる。返済と清算はバケット不足を理由に拒否しない。
5. **清算**: 統合先の規則に従い実行し、対象ロットと債務を原子的に更新。バケット不足、Sentinel 停止、汚染指定、証明の有無を清算の拒否理由にしない。

固定窓は窓境界の直前・直後にそれぞれ `K` を許容するため、任意の 10 分間での流出を `K` 以下に抑えるものではない。金額は借入実行時点の評価額であり、後の価格変動、既存の成熟担保や借入、別市場・別チェーン、未保護経路を含む損失の上限ではない。熟成により汚染が自動解除されることはない。

同一トランザクションや同一ブロックの取引も上記の永続会計を適用する。暫定仕様では追加の同一ブロック一律拒否や時間比例の線形解放は採用しない。IDEA の式は供給直後に即時枠がゼロになる一方、即時共有枠を許す記述と矛盾するためである。EIP-1153 はトランザクション終了時に破棄されるため、同一ブロック内の別トランザクションを識別する代替にはできない（[EIP-1153](https://eips.ethereum.org/EIPS/eip-1153)）。

コリドー機能を有効化する場合は、上記の増分会計と上限を維持し、§11 の連続2レーン・ペア別配賦・料金を追加適用する。

### 4.3 価格・失敗時の扱い

統合先が認めた資産ごとに価格ソース、最大経過時間、価格の単位、妥当な値域、L2 シーケンサー停止時の扱いを設定する。価格がゼロ、期限切れ、取得不能、範囲外、または演算オーバーフローの場合、影響する新規借入と担保削減は拒否する。返済と、統合先の安全な規則で実行できる清算は妨げない。価格障害中に安全に清算できるかは統合先に依存し、無条件の実行成功を保証しない。エラーは機械可読コードと市場・資産を返す。

### 4.4 汚染通知と解除

`flagTaint(evidenceId, user, asset, lotIds, quantities, expiresAt)` 相当の操作を認可済み Sentinel のみが呼ぶ。配列長、上限、重複、各数量、期限を検証し、証拠 ID 単位で冪等に適用する。§4.1 の claim 対応・残量を同時更新する。根拠とロットの関連性はオンチェーンで自動保証できず、認可主体の判断に依存する。権限侵害による誤指定への対応として、権限停止、異議申立て、訂正、操作上限と監査が必要である。イベントに通知 ID、対象、数量、根拠への参照、送信者を残す。根拠そのものの秘密情報は公開しない。承認済みの解除権限は理由・証拠 ID を付して指定分を解除でき、履歴を残す。期限到来時の自動解除や通知の最大期間は未決定であり、決まるまでは期限切れ通知を新規に受け付けず、既存ロックの解除は明示操作とする。誤検知訂正と鍵漏えい時の停止・再登録の手順を運用要件とする。

### 4.5 隔離保管

隔離エスクローは市場本体と資産・利用者ごとに残高を分離し、未熟成の対象資産を保持する。原則として受領、成熟後の統合先供給、利用者への返還を公開イベント付きで行う。凍結・返還失敗は当該エスクローの失敗として記録し、他の預入者の処理を巻き戻さない。管理者による任意の資産引き出しは不可。

**実装上の前提**: エスクロー内資産は、統合先が検証可能な担保として認識し、清算・差押えが原子的に実行できる場合のみ借入を裏付けられる。そうでなければエスクロー残高の借入可能価値はゼロとする。借入後の発行者凍結は清算不能や損失を生じ得るため、隔離だけで市場の無傷を保証しない。隔離対象の判定、資産別凍結単位、清算設計と可用性を実証するまで本機能は無効。

### 4.6 証明による例外

初期仕様では ZK バイパスを**無効**とする。ブラックリストに単一アドレスが含まれないことは資金経路全体の潔白を証明せず、空・古いリスト、途中送金、DEX、ブリッジを通した資金や証明の使い回しを防げない。実装候補は限定された集合への所属等、証明できる命題として別途定義する。証明が保証する範囲を利用者に明示し、「無実」の保証と呼ばない。

有効化には少なくとも、対象となる資金と金額のコミットメント、出所と残高の検証可能な関係、資金混合の扱い、受益者・市場・チェーン・資産・上限・有効期限・操作への拘束、ルートの真正性と鮮度、失効、nullifier の原子消費、リプレイ防止、回路と検証鍵のバージョン管理、独立監査を仕様化し実証すること。無効・期限切れ・ルート不一致・既使用証明は拒否する。例外による借入は §1 のバケット保証には含まれない。

## 5. Sentinel 機能要件

### 5.1 取り込み・追跡

確定済み／未確定を区別したブロック、トランザクション、receipt、対応 ERC-20 Transfer を取り込む。イベント ID は chain ID・block hash・transaction hash・log index とする。順序、再送、欠落を検出し、永続チェックポイントから再開できる。Pending 情報は観測可能な範囲の予測であり、確定イベントと区別する。プライベート取引、L2 sequencer、ノード差により観測や先回りを保証しない。

シードは出典、資産、数量、対象期間、登録者を持つ。ノードは時刻・トランザクション順序を含むイベント単位とし、同じアドレス間の往復も DAG として表現する。資金の混合時は資産ごとに数量と汚染割合を持つ比例配分（haircut）を用い、送付数量の `汚染残高 / 総残高` 相当を伝播する。小数・丸め・過去残高の基点を記録し、残高不明や履歴欠落は unknown とする。FIFO と比例配分は異なるため混用しない。複数シードの重複や自己送金による二重計上を防ぐ。実行可能な DEX・ブリッジの解釈器を個別登録し、未対応経路では推測で無汚染としない。上限ホップ、欠落、計算量制限到達は coverage に記録する。

### 5.2 再編成と通知

ブロック親ハッシュを検証し、reorg 発生時は共通祖先までロールバックし正規チェーンを再実行する。通知候補には根拠ブロックと最終性を含める。確定前通知の許容条件と補償手順を設定し、取り消された根拠に基づくロックは明示解除を提案・実施する。オンチェーン操作自体が reorg された場合は receipt と状態を照合して再送する。

通知のライフサイクルは `candidate → submitted → included → finalized`、失敗時は `failed/retry`、根拠喪失時は `retracted` とする。高優先手数料やバンドルを使っても相手より先に確定する保証はない。nonce、手数料上限、再送、冪等性、重複インスタンスのリーダー選出と鍵保護を設け、送信成功を最終確定と扱わない。検知が間に合わない場合も §4.2 の制限が独立して働く。

### 5.3 運用観測

取得遅延、最終処理ブロック、reorg、欠落、unknown 割合、候補・送信・確定・失敗数、オンチェーン残量、通知遅延と価格鮮度を記録し、閾値超過で通知する。鍵・秘密入力・個人情報はログに出力しない。ノード停止・再起動・障害からの復旧と照合手順を用意する。

## 6. シミュレータ

### 6.1 入力と実行

ブロック順の供給、借入、返済、引き出し、清算、移転、価格、対象市場設定と攻撃ラベルを読み込む。各データセットのチェーン、ブロック範囲、出典、取得時刻、ハッシュ、欠損、ラベル根拠を manifest に記録する。時刻や金額、重複・順序・スキーマを検証し、不足する価格やイベントは成功扱いせず、該当結果を `hold` または `failed` とする。Parquet は候補形式であり Rust/Polars の利用は実装上の選択肢。

実行はベースラインと同一入力・順序の対策ありシナリオを比較し、パラメータ、コード版、データ hash、乱数 seed、前提を保存する。拒否された取引後の行動は観測できないため、再試行・取引順序・価格への影響などの仮定を明示し、観測事実と反実仮想を分離する。再試行や経路変更をモデル化しない場合、その制約を出力する。

リプレイには、開始直前の基準ブロック番号・hash と出典・内容hash付き初期状態を必須とする。担保ロットの数量・供給時刻・満期・claim残量、既存負債・利息基点、市場設定・価格基点、実行モード、固定窓消費または全レーンの work・最終更新時刻、個別枠、適用待ち設定を含める。初期状態はモデル別に定義し、観測された担保・負債等の事実と反実仮想の limiter 初期値を区別する。イベントを先行再生して復元する場合は、基準状態と warm-up の範囲・根拠・hash を保存する。単なる一定時間の warm-up で古い負債等が消えると仮定しない。必要な状態を復元できなければ hold とし、空状態・全熟成・未使用枠に暗黙補完しない。全履歴再生とチェックポイント再開の一致を検証する。

§5 のイベント識別を再利用し、chain ID と正規 block hash・親hash・最終性を固定する。block number、transaction index、log index の昇順で再生し、同一位置の重複・競合hash・逆順・未解決reorgは拒否する。内部呼出やログのない操作が必要な場合は、対応するtrace順序を明示する。観測ログを並べ替えて対策効果を有利にしない。正規順序以外の順序実験は別シナリオとして保存する。

### 6.2 指標

| 指標 | 定義 | 評価目標 |
| --- | --- | --- |
| 被害阻止率 | `(ベースラインの攻撃者借入 USD - 対策後の攻撃者借入 USD) / ベースラインの攻撃者借入 USD` | 95% 以上を目標。分母ゼロは N/A |
| 正常ユーザー摩擦率 | 制限で拒否または延期された正常借入の利用意図数 / horizonを観測できた正常借入の利用意図数 | 0.05% 未満を目標。正常ラベル不明は分母から除き件数を別記 |
| 清算干渉率 | Aegis の追加制限で失敗・延期された清算意図数 / horizonを観測できた清算意図数 | 0%。統合先固有の失敗は別集計 |
| カバレッジ | 評価可能な操作数 / 対象操作数 | 欠損理由と併記。閾値はデータ選定時に確定 |

延期をモデル化する評価では、利用意図 ID と attempt ID、観測 horizon（秒またはブロック）、retry policy・上限、重複排除規則を事前に設定する。正常ユーザー摩擦率の分母は horizon 全体を観測できた正常な利用意図数、分子はそのうち Aegis により一度でも拒否・延期された利用意図数とし、再試行成功でも分子に1件として残す。期限内成功・期限内未成功は別集計する。期間末等で horizon が不足する意図は censored として分母から除外し、件数と理由を出す。清算の延期も同じ horizon・意図単位を用いる。意図の同定根拠がない場合は推測で束ねず、「初回観測取引の拒否率」と attempt 別結果のみを表示し、延期を含む目標 KPI は N/A とする。

件数・分母・未判定数・資産価格時点・期間・シナリオごとの値を出力し、未達や N/A を隠さない。IDEA にある事件名、具体的被害額や阻止額は検証前の例示であり、実績として扱わない。

## 7. 外部インターフェースと状態遷移

実装の ABI は統合設計の確定後に定義する。最低限の論理操作は `supply(user, asset, amount)`、`borrow(debtor, asset, amount, recipient)`、`repay`、`withdraw`、`liquidate`、`flagTaint`、`clearTaint`、`getBorrowStatus`、パラメータ変更と緊急停止である。呼び出し元、債務者、担保所有者、受取人の認可は統合先に整合させる。プレビューは価格・残量・ブロック時点を返し、次の取引成功を保証しない。

ロットの状態は `Unseasoned → Seasoned` を時刻条件で導出し、汚染は独立した数量属性、隔離は独立した保管属性とする。部分引き出し・清算で数量を減らし、残量ゼロなら終了。操作ごとに `SupplyRecorded`、`BorrowValidated`、`BucketConsumed`、`TaintFlagged/Cleared`、`Escrow*`、`ParameterScheduled/Activated`、`PauseChanged` を出力する。イベントに市場、対象、数量、単位、バージョンを含める。状態遷移とイベントは同一トランザクションで確定する。

## 8. 非機能要件と検証

性能は目標であり、ハードウェア、コンパイラ、ノード、データ規模、ウォームアップ、分位点、計測範囲を固定してから判定する。通常借入の追加ガス `8,500 以下`、Sentinel の 10,000 Transfer / block を 5 ms 以内、証明生成 1.5 秒以内・検証 220,000 gas 程度は IDEA 由来の**未検証目標**。ロット数や外部呼び出しによっては達成できず、保証ではない。10,000 件 / 5 ms と 1 件 / 50 μs は別の測定条件であり同一視しない。bounded な処理、超過時の拒否と監視を設計し、DoS を防ぐ。

ロット数の上限と到達時の供給拒否・統合規則を実装前に確定する。上限下での最悪ガスを測定し、ロット数の増加や上限到達を理由に返済・清算が実行不能にならないことを導入ゲートとする。

## 9. 導入順序と本番ゲート

1. **データとシミュレーション**: 対象市場と事件のデータ利用可否を確認し、入力検証・ベースライン・反実仮想を実装。計測不能な KPI は保留する。
2. **統合可能性の実証**: 対象市場の全操作経路と権限、担保・債務・清算の状態を列挙し、迂回不能な強制点をフォークで証明。成立しなければ当該市場への導入を停止。
3. **オンチェーン制御**: エポック、ロット、会計、価格障害、権限を実装し、不変条件と E2E を通す。ガス・ロット上限を測定。
4. **Sentinel と隔離**: 検知、reorg、再送、手動訂正を結合。隔離の担保認識と清算可能性は別ゲートで実証。
5. **証明例外**: 命題と信頼モデルを確定し、回路・統合・監査が完了した場合のみ有効化。

本番導入前に、対象チェーンと市場の特定、統合先承認、パラメータ・権限・オラクルの確定、脅威モデル、独立監査、障害訓練、ロールバック・移行計画、監視とオンコール、実データによる受け入れ結果を揃える。緊急停止時の既存ポジションの管理と復旧手順を検証する。

## 11. SPEC-ADDENDUM-001 Rev.2 — 連続回復・2レーン・積分料金

### 11.1 レビューの判定と保証範囲

本節は追加案 Rev.2 の統合設計であり、旧 §11 の固定窓・市場共通無料予約プールを置き換える。無条件の小口保証と点評価料金は v0.2 ですでに不採用だった。固定窓の境界バーストは旧仕様で認めた制約であり、連続回復へ変更する。実装・評価・監査前は無効。

外部レビューの計算は有理数で再検証した。容量 $2M、閾値60%、基準5 bps、追加1500 bps で使用率60→100%の $800k は、点評価 $120,400、100分割点評価 $31,003、積分 $30,400。全量0→100%は $31,000（1.55%）。これは料金モデルの比較であって、攻撃の利益・資金調達費・担保 LTV を含む収益性や実行可能性の証明ではない。1,200アドレス・250k gas/件・20 gwei・ETH=$3,000 なら gas の算術合計は $18,000 だが、1ブロックへの収容や L2 費用を実証しない。$60M の担保から $60M 借りられるとも仮定しない。

連続回復は任意の T 秒内を容量以下に抑える厳密な移動窓ではない。各レーン L の任意の長さ Δ の区間における消費上限は、丸めによる保守化を除き `K_L + K_L*Δ/T`。初期バーストと時間回復を許す。攻撃者は Sybil と経路変更で全レーンを消費できるため、DoS の完全無効化や正当利用者の絶対保証は主張しない。

### 11.2 予算・ルーティング

市場の容量 K をペア別 K_C に配賦し `ΣK_C <= K`。各コリドーは大口 W と小口 R を持ち、`K_W+K_R=K_C`。評価用比率は80:20、個別小口上限 F は $25,000。単位は全会計で USD 8 decimals を維持し、USD 0 decimals への変更は採用しない。未配賦容量の融通はしない。各市場は共通の回復時間 T（候補600秒）を使う。

個別小口使用量は債務者ごとに市場内全資産・コリドー共通で連続回復する。消費する金額は借入総額ではなく §4.2 の q または正の q_change。`q=0` は免除する。

**厳格なレーン選択**: `q <= max(0,F-userUsed)` の要求は全額 R に、それ以外は全額 W に割り当てる。レーンの残量不足なら全体を拒否し、他方への自動 overflow や部分約定はしない。大口要求から小口分を切り出す提案コードは不採用。これにより単一の大口要求は R を消費しないが、攻撃者が小口要求へ分割すれば R を消費できる。R 枯渇時は通常利用者も拒否され得る。個別枠内の同じ要求に対する W の任意指定だけを禁止する。F-userUsed と同額の要求が R 不足で拒否され、USD8の最小単位だけ増やすと W で成功する不連続は許容する設計判断とする。微増分を返済しても、既消費量を戻さず、総容量は増えない。ただし同じ経済的目的を持つ利用者が要求を操作してレーンを選ぶこと自体は防がない。見積もり・評価にこの境界を明示する。

R も W も積分料金を課す。EXEMPT は料金のみ免除（b=p=0）で、容量と通常の安全検査は維持する。返済・安全な清算は追加料金も枠消費も行わず、返済では使用量を減らさない。

### 11.3 連続回復と設定変更

最後の状態から `used(now)=max(0,used(last)-K_L*Δt/T)` として回復する。処理のたびに floor して時刻を更新すると端数が失われ、第三者の細分化呼出しで回復を遅らせ得るため、端数を保持する。

参照状態は `work = used*T`（単位 USD8×秒）。時刻を検証し、`work'=max(0,work-K_L*Δt)`、要求 q に対して `work'+q*T <= K_L*T` を確認して加算する。演算は十分な幅を使い、上限・積・時刻のオーバーフローを拒否する。個別枠は K_L の代わりに F を使う。ゼロ量呼出しや頻繁な同期で回復結果が変わらないことを検証する。価格変動・利息・返済で過去消費を復元しない。

容量・時間・料金・tier の変更にはタイムロックと設定版を使う。指定の有効化時刻まで旧設定で回復し、旧使用量を新設定の work 単位へ保守的に移す。容量引下げ時に残量を正に復元せず、使用量が新容量以上なら消費を拒否し時間回復を待つ。休止・再登録、版変更でも同様に過去使用量を保持する。遅延適用時は有効化時刻の前後を分けて計算する。設定版ごとに空のバケットを作る実装は禁止。

**モード・配賦構造の移行**: 固定窓と連続モードの相互切替、別コリドー・レーンへの容量移動、履歴と対応しない新IDへの再登録は、MVPでは即時変換しない。対象市場全体で正の依存増分を生む操作を停止し、移行開始時刻・旧設定版・状態hashを記録する。返済・安全な清算は継続する。最後の正の依存増分以降、旧固定窓長・旧連続回復時間・新回復時間の最大値以上を待ち、旧会計の全レーンと個別枠の使用量が解消したことを検証してから、再配賦と新モードを原子的に開始する。対象状態の解消は、有限な対象の列挙または全体の最終消費時刻・使用量上界からの検証可能な証明で確認する。どちらでも検証できない場合は解除しない。失敗・再試行・rollbackで停止開始時刻や履歴をリセットせず、旧新の双方が同時に貸し出す期間を作らない。

同一バケットの非構造的変更では、有効化時点の `work_new=ceil(work_old*T_new/T_old)` として使用額を過小化しない。容量増加は明示的に承認した追加バースト予算としてイベントに記録し、過去区間へ遡及適用しない。容量・時間が変わる区間は一つの「現在K」で包絡を判定せず、固定設定ごとの K_L+K_L*Δ/T と、変更点の使用額保存・承認済み追加容量・区間ごとの回復量を追跡する参照状態機械で検証する。移行クールダウンを跨ぐ場合も同じ状態機械を使う。低停止時間の直接変換は、この保守的移行とは別途仕様化・実証するまで無効とする。

### 11.4 積分料金と整数演算

各レーンの回復後使用量を a0、消費後を a1、容量を L とする。`u0=a0/L`、`u1=a1/L`。`x(u)=max(0,u-t/10000)/(1-t/10000)`。基準 b と追加サージ上限 p は bps。`L>0`、`0<=t<10000`、`b,p>=0`、`b+p<=10000` を検証する。

未丸め USD8 料金は `q*b/10000 + L*(1-t/10000)*p/10000*(x(u1)^4-x(u0)^4)/4`。回復で使用量が分数でも work による有理数を使う。最後に1回だけ USD8 単位で切り上げる。中間の閾値・WAD の切捨てを厳密な積分と同一視しない。参照モデルは任意精度有理数とし、Solidity の精度・演算上限・誤差を証明または differential test で拘束する。uint64 の USD 整数や無検証 cast は採用しない。

未丸め料金は同じレーン・同じ設定・回復なしの区間分割に対して加法的。各取引を切り上げれば N 分割合計と一括との差は USD8 単位で `0 <= split-single <= N-1`（参照演算が厳密な場合）。token 換算も各取引で切り上げるため追加の丸めがあり、「1 wei の差もない」は保証しない。100分割での100未満という上限は USD8 料金の同一レーン比較に限る。料金 token の wei と混同しない。

レーン変更、第三者取引、時間回復、価格・設定変更を含む分割は同じ積分区間にならず、全経路に対する料金不変性を保証しない。R/W への分割ルーティングが料金・可用性に与える影響も別途評価する。

### 11.5 担保ミキシングと最厳格ルール

コリドー ID は chain・市場・設定を識別する名前空間と実アセットペアから導出する。ただし設定版変更で使用量を初期化しない。wrapped asset への正規化、registered フラグ、認可された Hook 呼出しを必須とし、未登録を EXEMPT と扱わない。実ポジションから q と経路を計算し、利用者の担保・未熟成申告は信頼しない。

MVP は単一担保・単一負債制約を維持する。複数担保を有効化するには、借入資産ごとに**担保として有効化された未熟成ロット**の tier を再評価し、最厳格を強制継承する設計・PoC を追加ゲートとする。口座に存在する単なる token 残高は含めない。新規担保化には所有者の同意を要し、第三者の送り付けで既存口座の tier を変更させない。熟成済み枠だけで十分な q=0 の借入を無条件に制限しない。

一つの `dominantRiskCollateral` を全借入資産で使い回さない。同率 tier の複数ペアで容量・料金が異なる場合の支配ポリシーと共有使用履歴を先に定義し、担保の出し入れで別の満杯でない枠へ移る迂回を防ぐ。定義・実証までは複数担保操作を拒否する。成熟、価格変動、担保有効化・無効化、引出、移転、清算、設定変更でリスク状態を更新する。最悪ロット数でも返済・清算を妨げない。単純な最大 tier キャッシュだけでは更新・迂回防止を保証できない。

### 11.6 徴収と原子性

借入料金は借入資産で元本から控除しリザーブへ送る。元本全量で q と健全性を検証する。担保変更時は同じ資産を既存残高から徴収する。USD8 から token 最小単位へ有効な同一価格で切り上げ、料金超過・未対応 token・送金失敗は全体を revert する。

`maxFeeToken`、`minReceivedToken`、期限、設定版を利用者が拘束する。見積もりは取引順序を予約しない。回復時刻、work、個別使用量、ポジション変更、料金送金を原子的に確定し再入を防ぐ。イベントに market/corridor/設定版、時刻、q、選択レーン、料金（USD8/token）、受取額、使用量・残量を含める。リザーブ変更はタイムロックと監査履歴を必須とする。

提案の PackedDualBucket は256 bits、PackedCorridorMeta も `64+32+16+16+16+8+104=256` bits。UserRiskProfile は計416 bits で2 slots、address の dominant 値は借入資産依存性を解決しない。実装は USD8 と回復端数・設定移行を含むレイアウトを別途確定し、1 slot に収めるため精度を落とさない。Foundry storage layout で検証する。

### 11.7 評価用設定と受け入れ条件

コリドー容量候補は旧案どおり USDC/DAI→USDT/GHO=$10M、USDT→WETH=$2M、USDT→WBTC=$1.5M。各ペアは独立した候補で、総和は K=$2M と両立しないため再配賦が必要。各ペア内の80:20分割も未検証の評価値。STANDARD は目標8000 bps・追加200 bps、RESTRICTED は目標6000 bps・追加**4000 bps**を候補とする。基準5 bps、EXEMPT は0。40%追加でも全量0→100%の平均は4.05%（$2Mなら$81,000）であり攻撃不採算とは限らない。

- 任意のアドレス数で各レーンは回復を含む `capacity + capacity*Δ/T` の流量包絡を満たし、市場合計もその和以内。容量・回復予算を配賦し、返済や設定版で復元しない。
- $2M ペア、R=$400k、F=$25k の同一時刻の新規アドレスによる小口借入では16件成功、17件目は R 不足で拒否する。原案コードの overflow 有効時に総量$2Mまで W を使える挙動とは区別する。
- 単一の大口要求は W のみを使い R を変えない。分割攻撃は R を消費できるので、正常小口への絶対保証はない。
- t=599で満杯にしt=601では K*2/600 のみ回復する。頻繁な小刻み同期、長時間停止、同一timestamp、設定切替でも端数が消失しない。
- モード切替、容量の他ペア移動、休止・再登録、移行失敗と再試行で使用履歴を保存する。大口枠と小口枠の境界の直前・一致・最小単位超過と微増返済を比較する。
- 積分の閾値、100%、ゼロ容量、最大値、同一レーン100分割、USD8とtokenの別々の丸め境界、レーン切替を検証する。
- 混合担保は MVP で拒否し、拡張 PoC では少額ETH＋高リスク未熟成担保を低リスクと申告しても拒否または最厳格が適用される。第三者dust・担保の出し入れ・同率tier・複数負債で迂回しないことを検証する。
- 既存 q_change、未登録、代理借入、価格失効、徴収失敗、再入、slippage と期限、清算・返済の可用性を E2E で検証する。
- Rust の参照モデルと Solidity を照合し、原案／固定窓／連続2レーンの攻撃費用、正常ユーザーへの影響、欠損を比較する。実データ不足は hold とし、利益や gas・MEV の仮定を明示する。
