# aegis-flow

分散型レンディング市場において、担保を多数のアドレスに分散し、短時間に借り入れる攻撃の影響を抑えるためのプロジェクトです。未熟成担保に依存する借入を市場全体の共有枠で制限し、資金移動の追跡と再現可能なシミュレーションを組み合わせることを目指します。

> **開発状況：最小シミュレータが動作**
> 入力検証、固定窓の基本貸借会計リプレイ、評価レポートを CLI から実行できます。Sentinel は Transfer 収集と永続化・reorg 復旧に対応します。汚染追跡とオンチェーン貸借保護は未実装であり、実市場での安全性・性能・効果は未検証です。

## 設計の概要

- **共有バケット**：担保を供給単位ごとに熟成管理し、未熟成担保に依存する借入と、担保構成の変更による未熟成担保への債務の付け替えに、市場単位の共有枠を適用します。アドレスごとの分割による制限の迂回を防ぐ設計です。
- **汚染数量の会計**：汚染情報をアドレス全体ではなく、対象資産と担保ロットの数量に紐付けます。少額の送り付けによる無関係な担保の一律ロックを避けます。
- **Sentinel**：オンチェーンの資金移動を追跡し、汚染の可能性がある担保の通知を行うオフチェーンエンジンを計画しています。検知や取引への先回りは保証されません。
- **シミュレータ**：取引データを使って対策あり・なしのシナリオを比較し、借入の抑制、正常ユーザーへの影響、清算への干渉を評価します。

共有枠は固定時間窓ごと、単一チェーン上の単一市場ごとに適用する設計です。窓境界の前後ではそれぞれの窓の容量を消費できるため、任意の連続した時間内の流出額を同じ上限に抑えるものではありません。価格変動や既存債務、他市場、未保護の経路を含む損失の上限も保証しません。

## 保護範囲と未解決事項

保護には、対象市場のすべての担保変更・借入・負債移転を迂回できない形で検証する統合が必要です。任意利用のラッパーを既存市場に追加するだけでは、市場全体を保護できません。Aave V3/V4 との具体的な統合方法と対象市場は未確定です。

隔離エスクローは、隔離中の資産を担保として認識できることと清算可能性を実証するまで無効とします。ZK 証明による制限の例外も、証明する命題と信頼モデルの確定、実証、独立監査が完了するまで無効です。単一アドレスのブラックリスト非包含だけでは、資金の出所全体の安全性を証明できません。

対象チェーンの候補は Ethereum、Arbitrum、Base、Optimism です。各チェーンと市場での統合可能性、価格フィード、データ取得などは今後検証します。

## 今後の進め方

1. データを選定し、シミュレータによって対策の効果と利用者への影響を評価する。
2. 対象市場における迂回できない統合方法を実証する。
3. オンチェーン制御を実装し、会計の不変条件や障害時の動作を検証する。
4. Sentinel と隔離保管を検証し、条件が整った場合に証明による例外を検討する。

導入前の検証項目と未決事項は[機能仕様書](docs/SPEC.md)を参照してください。

## 開発環境

Rust 1.98.0（`rust-toolchain.toml`、rustfmt と Clippy を含む）と Foundry v1.8.6 を使用します。`rustup` と指定版の Foundry をインストールしたクリーンチェックアウトで、次を実行します。Foundry は初回ビルド時に Solidity 0.8.26 を取得します。

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
forge fmt --check
forge build
forge test
python3 scripts/e2e-node.py
python3 scripts/e2e-bucket.py
python3 -m unittest discover -s tests -v
python3 -m unittest discover -s tests -p e2e_sentinel.py -v
```

Solidity の EVM 対象は Cancun です。Ethereum、Arbitrum、Base、Optimism は対象候補であり、各チェーンの EVM 機能と市場統合の対応は未検証です。E2E スモークテストはローカル Anvil ノードの JSON-RPC 接続を確認します（Python 3 が必要です）。`e2e-bucket.py` は `forge build` 後のテスト用 harness をローカルノードに配置し、容量超過の拒否、窓境界での設定適用、操作失敗時の状態復元を確認します。実市場の担保・貸借機能の安全性は未検証です。

### 固定窓バケット（内部ライブラリ）

`contracts/src/FixedEpochBucket.sol` は USD8 整数の市場別消費を管理します。初期窓は Unix 時刻の `floor(timestamp / duration)`、設定変更は旧窓終了時に適用し、その境界を新しい窓の起点とします。遅延呼出しでは適用時刻から新しい長さで経過窓を計算します。窓は `(version, start)` で識別し、再初期化・適用待ち設定の上書きを拒否します。容量ゼロは正の消費を拒否し、窓長ゼロは不正です。返済による返却 API はありません。窓境界では前後で各容量を使えるため、厳密な移動窓の上限ではありません。

利用する市場が chain/market ごとの storage と呼出し権限を管理し、借入・担保変更と同一トランザクション内で `consume` を呼ぶ必要があります。ライブラリの設定イベントは市場 ID を持たないため、統合者は市場を特定する監査イベントも発行してください。`initialize` / `schedule` / `sync` も内部関数であり、公開管理 API やタイムロックは #21、実市場への統合は #8・#17 の後続作業です。テスト用 `BucketHarness` は認可を持たず、本番用コントラクトではありません。連続モード・価格評価・管理者権限はこのライブラリに含みません。

### シミュレータ入力の検証

架空データを使った入力検証は次のコマンドで実行できます。

```sh
cargo run --locked -p aegis-sim -- crates/aegis-sim/examples/manifest.json crates/aegis-sim/examples/data.json
```

manifest はチェーン ID、対象ブロック範囲、出典、取得時刻（Unix 秒）、ラベル出典、データファイルの SHA-256、判明している欠損を記録します。入力はイベント、ブロック時点の USD 価格（小数点以下 8 桁の整数）、市場・資産別 LTV、イベント単位のラベルを JSON で指定します。金額は最小単位の 10 進文字列です。対応イベントは `supply`、`borrow`、`repay`、`withdraw`、`liquidation`、`transfer`、ラベルは `attack`、`normal`、`unknown` です。入力例の値は架空で、実事件とは関係ありません。

入力 v2 は出典・ハッシュ付きの初期状態と正規ブロック列を必要とします。v1 は保留となります。詳細は[入力仕様](docs/DATASET.md)を参照してください。

`READY`（終了コード 0）は対応する形式の構造検証を通ったことのみを示し、出典の真正性、全イベント・初期状態・設定履歴の網羅、ラベルの正しさ、KPI の評価可能性を保証しません。価格・設定・ラベルの欠落や申告された欠損は `HOLD`（2）、不正形式、ハッシュ不一致、価格ゼロ、重複、順序違反は `FAILED`（1）になります。価格は各イベントと同じブロックの値を要求します。設定はデータセット内で一定として扱うため、設定変更や対応できない履歴がある場合は manifest の `missing` に記載し保留にしてください。基本会計リプレイは下記で利用できます。対応範囲の KPI は下記の評価レポートで確認できます。

### 基本会計リプレイ

```sh
cargo run --locked -p aegis-sim -- --replay crates/aegis-sim/examples/replay-manifest.json crates/aegis-sim/examples/replay-data.json
```

架空の100 USDT供給・50 USDT借入要求を、通常会計と未熟成枠30 USDの保護あり会計で比較します。通常会計は借入を許可し、保護あり会計は枠不足で拒否します。JSONには要求ごとの判定・理由・消費額と、両モデルの最終チェックポイントを出力します。これは資産価格と与信条件に基づく会計モデルであり、実際のAaveの流動性・取引実行・gas・MEVを再現するものではありません。

供給・借入・返済・引き出し、ロット別熟成、固定窓、価格と利息指数、再開用のチェックポイントを扱います。連続モード、清算、移転、適用待ち設定、claim付き担保の引き出し、実行境界が不明な同一取引内の複数操作は現在未対応で HOLD になります。利息・価格・清算閾値や正確な債務持分が不足する入力も HOLD とし、補完しません。意図に基づく再試行はまだモデル化せず、観測要求を一度ずつ再生します。

### 評価レポート（最小動作例）

リポジトリ直下で実行します。Rust を指定版でインストールすれば、シミュレータに RPC・ウォレット・Foundry は不要です。

```sh
cargo run --locked -p aegis-sim -- --report crates/aegis-sim/examples/replay-manifest.json crates/aegis-sim/examples/replay-data.json > report.json
```

この架空例は baseline の借入50 USD、protected の借入0 USDを出力します。`metrics.attack_prevention` の分子・分母はともに `5000000000`（USD8）です。これは架空データの手計算確認であり、実事件の阻止実績ではありません。正常意図・清算の分母はなく N/A です。

JSON は両モデルの attempt 結果・最終状態、指標の分子/分母・未判定数、入力/manifest/コード/設定の SHA-256、設定・価格方針・期間・再試行の前提を含みます。浮動小数点の百分率ではなく正確な整数比を保存します。乱数は使わず seed は null。同一実装・入力で同じ JSON を再現できます。

意図の根拠と ID がある正常借入のみ horizon と再試行を集計します。再試行は入力に明記された要求だけを観測順に再生し、追加生成しません。期間末で horizon 不足の意図は censored とし摩擦率から除外します。ID 不足時は意図を推定せず、観測された正常借入取引の追加拒否率だけを表示します。実データの取得・完全性確認は [評価データ調査](docs/EVALUATION_DATA.md) のとおり保留です。詳細な集計契約は [入力仕様](docs/DATASET.md) を参照してください。
